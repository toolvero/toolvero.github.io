CIDR Explained: /24, /16, Subnet Masks and Usable Hosts

A practical guide to reading IPv4 CIDR notation, understanding subnet masks and calculating network boundaries.

What does /24 mean?

CIDR (Classless Inter-Domain Routing) writes an IPv4 network as an address followed by a prefix length, for example 192.168.1.0/24. The prefix tells you how many of the 32 IPv4 bits identify the network. The remaining bits are available for addresses inside that network.

*The familiar “minus two” rule applies to conventional IPv4 subnets that reserve network and broadcast addresses. /31 and /32 have special uses and should not be treated with that simple rule.

Network, broadcast and host range

For 192.168.1.0/24, the network address is 192.168.1.0 and the broadcast address is 192.168.1.255. In the conventional host model, addresses 192.168.1.1 through 192.168.1.254 are available to hosts.

Quick rule: every time the prefix grows by one bit, the address block is divided in half. A /24 has 256 addresses, a /25 has 128 and a /26 has 64.

Common mistakes

  • Confusing the number of addresses with the number of conventionally usable host addresses.
  • Assuming two IPs with similar first octets are in the same subnet without checking the prefix.
  • Forgetting that the prefix, not the old classful A/B/C model, defines the modern network boundary.

Example: splitting a /24

Splitting 10.10.20.0/24 into two equal networks produces 10.10.20.0/25 and 10.10.20.128/25. Each block contains 128 addresses. This is the basic idea behind subnetting: borrow host bits to create additional network prefixes.
