HTTP Security Headers Explained: CSP, HSTS and Browser Protections

Understand common response headers that instruct browsers to enforce security controls.

Why response headers matter

Web servers can send policy headers with a response. These do not replace secure application code, but they can reduce exposure to classes of browser-side attacks and unsafe behavior.

HeaderPurpose
Content-Security-PolicyControls permitted content sources and other browser behaviors.
Strict-Transport-SecurityTells supporting browsers to use HTTPS for the host for a defined period.
X-Content-Type-OptionsWith nosniff, reduces MIME-type sniffing.
Referrer-PolicyControls how much referrer information is sent.
Permissions-PolicyControls access to selected browser features.

CSP requires application knowledge

A strict Content Security Policy can be powerful, but copying a policy from another site can break scripts, styles or embedded resources. Build and test the policy against the actual application.

HSTS requires HTTPS readiness

HSTS tells browsers to prefer HTTPS for a period of time. Administrators should understand the scope, max-age and optional subdomain behavior before deploying it broadly.

Use headers as defense in depth

Security headers complement TLS, secure cookies, input handling, authorization and other application controls. Treat an analyzer score as a diagnostic aid rather than a guarantee that a site is secure.
