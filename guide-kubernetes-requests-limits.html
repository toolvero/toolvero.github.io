Kubernetes Requests vs Limits Explained

Understand how Kubernetes CPU and memory requests and limits affect scheduling, capacity and runtime behavior.

Requests and limits solve different problems

A resource request tells the Kubernetes scheduler how much CPU or memory to account for when placing a Pod. A limit defines a runtime ceiling. They are related, but they are not interchangeable.

CPU example

resources:
  requests:
    cpu: "250m"
  limits:
    cpu: "500m"

250m is 0.25 CPU and 500m is 0.5 CPU. CPU use above a configured limit can be throttled.

Memory behaves differently

Memory cannot be throttled in the same way as CPU. A container that exceeds its effective memory limit can be terminated for out-of-memory conditions, so arbitrary low memory limits can reduce reliability.

Estimate workload totals

Multiply per-container requests by containers and replicas to understand the resources represented by the workload. Keep cluster overhead and other workloads separate from this estimate.
