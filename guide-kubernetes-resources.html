Kubernetes CPU & Memory Requests and Limits Explained

A practical guide to cores, millicores, Mi, Gi, requests, limits and why resource settings matter.

CPU units

Kubernetes CPU is measured in CPU units. 1 represents one CPU core (or equivalent virtual CPU scheduling capacity), while 500m means 500 millicores, or 0.5 CPU.

ValueEquivalent
100m0.1 CPU
250m0.25 CPU
500m0.5 CPU
1000m1 CPU

Memory units

Memory values commonly use binary units such as Mi and Gi. For example, 512Mi is half of 1Gi.

Requests vs limits

A request is used by the scheduler when placing a Pod and represents the resource amount requested for scheduling. A limit constrains resource usage according to Kubernetes and runtime behavior. CPU and memory react differently when limits are exceeded, so they should not be treated as interchangeable controls.

Example

resources:
  requests:
    cpu: "250m"
    memory: "256Mi"
  limits:
    cpu: "1"
    memory: "1Gi"

Choose values from measurements

Resource settings should be based on observed workload behavior, service objectives and cluster capacity. Extremely low requests can distort scheduling, while arbitrary limits can create performance or reliability problems.
