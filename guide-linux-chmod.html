Linux chmod Explained: 755, 644, rwx and File Permissions

Understand owner, group and other permissions, and learn how symbolic rwx maps to numeric chmod values.

The three permission groups

Traditional Unix permissions are shown for three groups: the file owner, the file's group and everyone else. Each group can have read (r), write (w) and execute (x) permission.

PermissionLetterNumeric value
Readr4
Writew2
Executex1

Why 755 means rwxr-xr-x

Add the values within each group. 7 = 4+2+1 gives read, write and execute. 5 = 4+1 gives read and execute. Therefore 755 becomes rwxr-xr-x.

chmod 755 script.sh

This gives the owner read/write/execute access while group and others receive read/execute access.

Why 644 is common for regular files

644 maps to rw-r--r--: the owner can read and modify the file, while group and others can read it. It is a common pattern for non-executable files, but the correct permission always depends on the application's security requirements.

chmod 644 config.txt

Directories are different

On a directory, execute permission controls traversal. A user may need execute permission on each directory in a path to access files beneath it. This is why blindly applying file-style permissions recursively can break applications or expose data.

Avoid chmod 777 as a shortcut

777 grants read, write and execute permissions to owner, group and everyone else. It may make a permission error disappear, but it usually grants far more access than necessary. Identify which user or service needs access and grant the minimum appropriate permissions instead.

Symbolic chmod

Numeric mode is compact, but symbolic chmod can express targeted changes such as adding execute permission to the owner:

chmod u+x deploy.sh

Here u means user/owner, + adds a permission and x means execute.
